# Evidence record

One record per participant and exposure, filled in by the researcher after the participant has submitted the questionnaire. Use the participant code, never a name. This record works for both studies.

- **General study:** one record per participant (one prototype, one exposure).
- **Comparative study:** two records per participant, one for each exposure.

The evidence rules are in the [test plan](test-plan.md#evidence). The four sources used below are **R** (a screen recording shows it), **S** (the participant says so in the questionnaire), **R+S** (both agree) and **U** (no evidence either way, written as **Unknown**). Give every finding a value and a source. Quote exact words with their question ID or recording time. Do not write a self-reported action as observed. Unknown is a valid value and is neither a failure nor a success. Write N/A only when the question did not apply.

Ratings and answers stay in the questionnaire export. The knowledge check measures reported understanding and is not observed behaviour. Do not score it until all responses are in. The answer key is only in the [findings template](comparative-study/comparison-and-findings-template.md).

## 3. The planted error

**When it counts.** In the general study it applies to the participant's only exposure. In the comparative study it applies to the **first exposure only**. On the second exposure, skip the table, write any exact words they say about the planted content under "Other notes" and do not count them. Second-exposure observations are not equivalent primary evidence. A report made only after seeing the second version is not evidence of noticing on the first.

Keep the four observations separate. Do not combine them into one trust score. Do not infer trust, competence or understanding from a failure to notice.

| Observation | Value | Source | Exact words and notes |
|---|---|---|---|
| 1. Noticed the Thursday/Friday mismatch | See the values below | | |
| 2. Acted on it. What they say they would change, whether they opened the edit screen and whether they attempted to save | | | |
| 3. Sent Sam's reply unchanged, and the participant's explanation | | | |
| 4. Saw it as Aria's mistake or their own misreading | | | |

Values for observation 1:

| Value | Meaning |
|---|---|
| While reading the draft | They report noticing it as they read the draft. |
| After seeing the edit screen | They report noticing it only after opening the edit screen. |
| Only after re-reading | They report noticing it only after going back to the draft. |
| Reported not noticing | They say they did not notice it. |
| Unknown | There is not enough evidence either way. |

- The main place to look is question D3, which does not name the error. A recording can show that they opened Sam's edit screen or went back to the draft. It cannot confirm that they noticed anything.
- "Reported not noticing" is not the same as "Unknown". Use the first only when the participant said so. "Confirmed not noticing" is not offered, because nobody can confirm that someone did not notice something.
- The prototypes cannot demonstrate a successful correction, so a completed correction cannot be recorded. Sam's draft should never show Friday. If a recording shows it, record a prototype fault in section 1.
